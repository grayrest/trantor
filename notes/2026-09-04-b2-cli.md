# B2 — `roc:cli` + both drivers (first end-to-end milestone)

Gate B2 of [`plans/2026-09-04-basic-cli-port.md`](../plans/2026-09-04-basic-cli-port.md).
Fixture: `tests/golden/b2-cli/` (`verify.sh`). Implements P8/P9/P11/P12 over
B0's resources and B1's streams.

## Result ✅ (host compiled first try)

A basic-cli hello-world runs **unchanged** on the `main!`-compat world and its
`run!`-native twin runs on the `run!` world, with identical output: `hello from
basic-cli on trantor` / `user: grayrest` / `args: a,b` on stdout,
`(diagnostic on stderr)` on stderr, exit 0. basic-cli 0.21's `Stdout.roc`,
`Stderr.roc`, `Stdin.roc`, `Tty.roc` are **byte-identical to the cache** —
`verify.sh` `cmp`s them — with `import Host` intact.

## The migration-ease trick: a pure-Roc `Host`

basic-cli's modules `import Host` and call `Host.stdout_line!` etc. Rather than
rename that import (H5's approach), B2 ships a **pure-Roc `Host` module with
bodies** (`components/host-shim`, `kind = "roc"`) that reconstructs basic-cli's
`Host` surface over the WASI-shaped primitives: `stdout_line!` =
`CliOut.get_stdout!` → `Streams.write!`; `stdin_line!` → `CliIn.read_line!`;
`env_var!` → `CliEnv.var!`. It is the D2 derived layer *underneath* basic-cli's
own derived layer — two pure-Roc tiers over one primitive tier. Result: **zero
edits** to basic-cli's files. This generalizes: any basic-cli module that only
imports `Host` + `IOErr` ports verbatim once `Host` covers its leaves.

## Primitives (WASI boundaries, P6)

`roc:cli/stdout`+`stderr` (`get_stdout!/get_stderr! → OutputStream`),
`roc:cli/stdin` (`get_stdin! → InputStream`, plus host-buffered `read_line!` /
`read_to_end!` — WASI leaves line-splitting to libraries; std's buffered Stdin
is the honest sync form), `roc:cli/environment` (`arg_count!/arg_at!`,
`var!`, `env_count!/env_at!`, `platform!`), `roc:cli/terminal` (raw mode,
no-ops here). One host crate, `cli-host`, for the whole package (P9).

## Findings

1. **count+at sidesteps R-B5 cleanly.** `get-arguments`/`env_dict` return
   lists of strings, and the pinned glue has no host-side `RocList<RocStr>`
   constructor. `arg_count!`/`arg_at!` (and `env_count!`/`env_at!`) let the
   derived `Env.args!`/`dict!` build the list **in Roc** with a `collect!`
   loop — no host list construction at all. The `main!`-compat driver's adapter
   is just `main!(Env.args!({}))`. R-B5 is closed by construction.
2. **`Env` is re-expressed, not verbatim (P11).** basic-cli's `Env.roc` is
   built on `OsStr`/`Path` — `cwd!`/`set_cwd!`/`exe_path!`/`temp_dir!` are
   `Path`-typed and `var!`/`dict!` take `NativeOsStr`. With OsStr dropped, B2
   ships a Str-based `Env` (`args!`, `var!`, `var_str!`, `dict!`, `platform!`);
   the `Path`-typed four arrive in B3 with `roc:path`. Documented deviation.
3. **`?` does not unify two open error rows in this compiler.** An app doing
   `Stdout.line!(…)?` inside `main! : … => Try({}, [Exit(I32), ..])` fails:
   "`?` returns `[StdoutErr(IOErr), ..]` … body evaluates to `[Exit(I32), ..]`".
   The idiom that compiles is `?? {}` (discard) or an explicit `match`. Worth
   knowing for every ported example app.
4. **Each stdout write mints a fresh `OutputStream` resource and drops it** —
   wasteful but correct, and it exercised B0's drop-balance under real load
   (hundreds of resources per run, no leak). A cached handle is an easy later
   optimization inside `cli-host`.
5. Effectful helpers need the `!` suffix (`collect!`, `out_write!`) and a
   `{} =>` annotation means one unit argument (`|{}|`, not `||`) — two
   compiler rules that bit the first draft.

## Exit ✅

`verify.sh`: basic-cli's four modules byte-identical to 0.21; both worlds
compose, build, and produce the expected stdout/stderr/exit. B3 may build the
capability filesystem and `roc:path`, restoring `Env`'s Path-typed surface.
