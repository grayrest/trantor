# H0c archive symbol-collision scan (`hematite scan`)

Wires the R2 / H0c policy from [`notes/2026-09-04-h0-link-shape.md`](2026-09-04-h0-link-shape.md):
at compose time, reject a global symbol defined by more than one component
archive, because the roc link resolves such a duplicate **silently by archive
order** (first-in wins, later copies never loaded) — benign when the copies are
identical, memory-unsafe when they differ (two vendored sqlites with different
struct layouts sharing one implementation). The linker will not catch it, so
hematite must.

Code: [`src/scan.rs`](../src/scan.rs), subcommand `hematite scan <world-dir>
[--world w] [--target arm64mac] [--targets-dir dir]`. Proof: the `nm-scan`
golden fixture; the gate is run after `cargo` in every fixture's `verify.sh`.

## The discriminator (measured, not guessed)

The whole difficulty is telling a real clash from the thousands of symbols two
Rust staticlibs legitimately share. `nm -m` on the real fixture archives settled
it — and overturned the first hypothesis:

- **Strong-vs-weak does NOT separate them.** Rust's `linkonce_odr`
  monomorphizations are emitted **plain `external`** on this toolchain (Mach-O
  LTO objects), not `weak external`. Two clean component archives share ~90+
  plain-external `__R…` symbols. So a weak-flag filter would flag all of them.
- **The split that works:** flag a symbol that is defined **plain `external`**
  (the attribute right after `)` in `nm -m` is exactly `external` — not
  `private external`, `weak external`, `weak private external`, or
  `non-external`) in **≥2 components**, then exempt:
  - **Rust-mangled names** (`__R…` v0, `__Z…` legacy). The v0 mangling embeds a
    per-crate disambiguator hash, so a shared name means byte-identical code —
    ODR-safe by construction. Different crate/version ⇒ different hash ⇒
    different symbol ⇒ no clash. Dropping these is sound.
  - **non-plain-external** definitions: `private external` (LSE atomics
    `__aarch64_cas*`, hidden builtins) and `weak external` are hidden or
    coalesced and cannot first-wins-collide at global scope. compiler-builtins
    softfloat (`___multi3`, `___adddf3`), libunwind (`__Unwind_*`), `_memcpy`
    all land here.
  - the **roc runtime** (`_roc_alloc`…): single-provider by construction
    (resolve enforces exactly one `provides_runtime`), listed for defense +
    documentation.
  - names the world declares shared via **`[world].shared_symbols`** (exact or
    trailing-`*` prefix glob; matched against the source name, leading `_`
    stripped).

What remains is exactly the footgun: an **unmangled, plain-external** symbol (a
vendored native's `sqlite3_*`, or a hand-written host `#[no_mangle]`) defined by
two components.

## Findings

- **Every one of the 15 real golden worlds scans clean.** b6-net and b8 share
  heavy rustls / ring / hashbrown / bytes / temporal_rs ODR generics between
  `http-host`, `testnet-host`, `temporal-host` etc. — all `__R…`, all exempt.
  A clean sole-vendor world's residual collision set is empty. This is the
  proof the exemption model has no false positives, not an assertion.
- **`nm -m` inserts annotations** (`[cold func]`, `[referenced dynamically]`)
  **between the attrs and the name.** The name is the *last* whitespace token —
  taking the text right after `external ` captured `[cold func]` and defeated
  the mangling filter (49 false positives on b6-net until fixed). Locked in by a
  unit test.
- **Xcode `nm` exits nonzero** on rust-LLVM archives it can only partially read,
  yet still prints the symbols it can — so exit status is ignored and stdout is
  used regardless (the fixtures' `{ nm … || true; }` idiom, in Rust).

## Decisions

- **D-scan-1** A separate `scan` subcommand, not a phase of `compose`. `compose`
  stops at sources (D13); the scan needs *built* archives, so it runs after
  `cargo`. Folding both into one pipeline is the still-open "drive the toolchain
  from the tool" gap.
- **D-scan-2** Archives are derived directly from `world.components` (every
  non-`roc` component → `lib<sanitize(name)>.a`), independent of `resolve`, so a
  not-fully-wired world can still be scanned. Order among colliders (which the
  linker resolves by) is reported but not relied on — rejection is the
  correctness property; naming the winner is diagnostic sugar.
- **D-scan-3** The escape hatch is per-symbol globs under `[world]`, not a
  per-dependency declaration — the scan operates on symbols, and one `sqlite3_*`
  entry covers a whole vendored library. No baseline world needs it (sole-vendor);
  it exists because the policy requires the hatch, and a genuinely shared native
  must be declared, never silently first-wins.

## Folded into `hematite build` (2026-09-08)

The scan is no longer a `verify.sh` step: `hematite build` (`src/build.rs`) now
drives the whole pipeline — compose → roc glue → cargo → stage → optional
`prelink.sh` → **scan** → roc check → roc build — with the scan in its proper
place, after the archives exist and before the link. It supersedes the 15
per-fixture `build.sh` scripts (retired); each `verify.sh` calls `hematite
build`. `compose` stays a separate pure source-emitter (D13), so byte-for-byte
and pre-build inspection checks still compose without building.

**D-scan-4** The one fixture-specific pre-link step (the turso macOS sysroot)
is an optional `<world-dir>/prelink.sh` hook `build` runs after staging — kept
out of the manifest, since only the turso world needs it and it is host-SDK
setup, not composition data. Uniform staging = exactly the archives
`resolved.archive_order` names (the link set), which subsumes both the
stage-all and the stage-selective build.sh variants.

## Still open

`hematite build` shells out to `roc`/`cargo` rather than embedding them (fine —
they are external tools). No consumer needs more of the pipeline inside the
tool today.
