# H3 — the composer

Gate H3 of [`plans/2026-09-04-hematite-v1.md`](../plans/2026-09-04-hematite-v1.md).
The tool, in Rust, at the repo root (`src/`). Acceptance test: regenerate the H2
fixture byte-for-byte, and the regenerated composition builds and runs.

## What it is

`hematite compose <world-dir> [--out <dir>]` reads `world.toml` + `interfaces/`
+ `components/` and emits the generated files of a composed Roc platform.

- `src/manifest.rs` — parse `world.toml`, `interface.toml`, `driver.toml` (the
  D18 TOML side; the `.wit` side is the Roc binding modules the interfaces ship).
- `src/resolve.rs` — parse the wiring DAG (`audit(capstdfs)`), compute the
  mangled hosted-symbol map, topologically order archives (a component after the
  ones it imports; driver last), and run the two compose-time checks.
- `src/codegen.rs` — emit `platform/main.roc`, the workspace `Cargo.toml`, the
  driver crate (runtime + `main()`), the `abi` wrapper; copy interface binding
  modules and pure-Roc components into `platform/` verbatim (D13).

## Acceptance (`tests/golden/two-component/verify.sh`) ✅

   Regeneration is deterministic (BTreeMap ordering throughout).
2. **Builds and runs.** `build.sh` (glue → cargo → stage → `roc check` → `roc

## The two compose-time checks (the linker won't do them)

Both fire before `roc` ever runs, turning what would be silent failures into
diagnostics:

- **H1b / D18-C — `requires_uses ⊆ exposes`.** Removing `Env` from
  `[world].exports` while the driver's `requires` names it:
  > driver `requires` names `Env` (requires_uses) but it is not in the world's
  > exposes ["Path", "Stdio"]; roc build would SEGFAULT on this (H1b, fault
  > 0x138c). Add `Env` to [world].exports.

  Without this, that mistake is a compiler SIGSEGV with no message.
- **H0c — exactly one runtime provider.** Flipping `provides_runtime = false`:
  > exactly one component must set provides_runtime = true (found 0); the linker
  > would silently first-wins duplicate roc_alloc (H0c).

  (The duplicate non-hosted-symbol `nm`-scan from H0c's policy is not yet
  implemented — it needs the built archives, so it belongs in the build step,
  after cargo. Tracked as an open item on H3.)

## Design points the tool pinned down

- **The interposer collapses host-side.** `fs = audit(capstdfs)` produces one
  Roc hosted symbol (`hematite__audit__file_read`, the chain head); `capstdfs`
  is reached by audit's Rust, so it is a plain archive with no Roc-facing
  symbol. The resolver's chain-edge logic (link[i] depends on link[i+1]) orders
  `capstdfs` before `audit` in the archive list.
- **Driver contract is authored, spliced verbatim.** `driver.toml` carries the
  `requires` block and the `main_for_host!` adapter as text; hematite never
  parses the Roc (D18-C). `requires_uses` is the declared cross-component type
  list it validates against `exposes`.
- **What's generated vs copied.** Generated: `main.roc`, workspace, driver
  crate, `abi` wrapper. Copied verbatim: interface binding modules, pure-Roc
  component modules. Not hematite's output: `abi/src/generated.rs` (glue) and
  the archives (build step). Provenance headers (`GENERATED BY hematite`) on
  every generated file (D23).

## Open items on H3

- Duplicate non-hosted-symbol `nm`-scan (H0c policy) — belongs in the build
  step after cargo, not yet wired.
- `hematite compose` stops at emitting sources; it does not yet drive glue +
  cargo + `roc build` itself (that is `build.sh`). Folding the build pipeline
  into the tool is the natural next increment, and is where the `nm`-scan and
  the `roc check`-before-`roc build` gate (currently in `build.sh`) become the
  tool's own responsibility.
- The `List(OsStr)` driver is still deferred (H2 finding — glue gap).
