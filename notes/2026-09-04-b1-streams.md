# B1 — substrate: `roc:io/error` + `roc:sync-io/streams`

Gate B1 of [`plans/2026-09-04-basic-cli-port.md`](../plans/2026-09-04-basic-cli-port.md).
Fixture: `tests/golden/b1-streams/` (`verify.sh`). Implements P7/P9/P10's
substrate on top of B0's resources.

## Result ✅ (first build)

One `InputStream` resource served **two backings** — an in-memory `Cursor`
(read 11 bytes) and a real file (read 720 bytes == `wc -c world.toml`) —
through the `Stream` trait. `live=0` at report: both stream handles were
dropped, exit code 11. The unified-stream substrate P7 chose works, and the
polymorphic backing (file vs memory vs, later, socket) is a `Box<dyn Read>`
behind one resource handle.

## What was built

- **`roc:io/error`** — `IOErr`, basic-cli's real 10-variant nominal, the single
  definition site (D16). Glue emits per-reach twins (`StreamsIOErr`, `IOErr`,
  `FileIoIOErr`) — structurally identical, host constructs each (the D7/D16
  observation from H2, now at three reach paths).
- **`roc:sync-io/streams`** — `InputStream`/`OutputStream` as `Box(U64)`
  resources (P5), `read! : InputStream, U64 => Try(List(U8), …)`,
  `write! : OutputStream, List(U8) => Try({}, …)`. A resource crosses the
  boundary typed as **`*mut u64`**.
- **The core/host crate split (the P9 shared-substrate shape, done safely).**
  `sync-io-core` is an **rlib** holding the `Stream` trait and the resource
  constructors (`input_stream(Box<dyn Read>)`) with **no `#[no_mangle]`
  symbols**; producers (`memory`, `file`, later filesystem/sockets/stdio)
  cargo-depend on it. `sync-io` is the **staticlib** owning the hosted
  `read!`/`write!` symbols. Why the split: cargo bundles an rlib into every
  dependent staticlib, so a `no_mangle` in the shared crate would be defined in
  N archives — the H0c silent-first-wins footgun. Keeping exported symbols out
  of the shared rlib is what makes "shared library, not cross-component hosted
  call" (P9/H2) actually safe.

## Findings

1. **No `Drop` on bare `RocStr`/`RocListWith`** in this glue (only `RocOwned`).
   Combined with the owned-argument contract (B0), every hosted fn taking a
   `Str`/`List` arg must `.decref(host)` it explicitly. `read!` releases its
   handle via `resource::with`; `write!`/`Memory.open!`/`FileIo.open!` decref
   their list/str args. **Pre-existing leak surfaced:** H2's and H5's stdio
   components take `RocStr` args and never decref them — a quiet per-call leak
   that never failed a test because nothing gauged it. Tracked as a cleanup.
2. **`RocListWith::from_slice(&[T], host)`** (T: Copy) exists — `read!` builds
   its `List(U8)` result with it; no manual list allocation needed for byte
   lists. (The refcounted-element `RocList<RocStr>` constructor is still the
   H2/R-B5 gap; B2's `main!`-compat driver must not depend on it.)

## Exit ✅

`verify.sh`: composes, builds, runs; asserts exit 11, "read 11 bytes", "read
`wc -c world.toml` bytes", and `live=0`. B2 may build stdio over these streams.
