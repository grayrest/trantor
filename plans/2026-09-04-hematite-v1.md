# Plan: hematite v1 — a component composition system for Roc platforms

**Design log:** [`notes/2026-09-04-hematite-design-log.md`](../notes/2026-09-04-hematite-design-log.md) (D1–D23, all resolved).

**Upstream track this depends on:** the rust-glue redesign
(`~/Repositories/roc/plans/2026-07-30-rust-glue-redesign.md`) — specifically
Phase 1 items 15–16 (ABI fingerprint + `roc_abi_assert!()`), which are what make
H5's Tier 1 prebuilt-archive reuse sound rather than a hope. v1 does not *block*
on them; without them Tier 1 ships with a `stat`+shasum fingerprint and a loud
warning instead of a link-time failure.

**Definition of v1:** hematite composes a declared world — interfaces, host
components, pure-Roc components, and one driver — into an ordinary Roc platform
that a stock `roc build` consumes. Proven by: seahaven and basic-cli
interchangeable behind one interface set; an app that extends the baseline
without a Rust toolchain (Tier 1) and one that extends it with host code
(Tier 2); and roc-solid `platform-im` composed as the closing scaling gate.
Tower is post-v1.

**Prime directive for the whole plan:** the tool is extracted from a
hand-written composition, never designed ahead of one. H2 produces the artifact
H3 must reproduce byte-for-byte. Any gate that finds itself designing a
resolver before H2 exists has gone off-plan.

---

## Architecture at a glance

```
world.toml + *.wit                        hematite (Rust)
─────────────────────                     ───────────────
interfaces  (bodiless, WIT-shaped)  ──►   resolve DAG, unify versions
components                                  │
 ├─ host      (Rust/Zig source)             ├─► platform/main.roc      [generated]
 ├─ pure-Roc  (derived layers, shims)       │     requires  ← driver, spliced verbatim
 └─ driver    (owns requires/provides/main) │     exposes   ← world export list
                                            │     hosted    ← mangled union
wiring:  fs = audit-log(cap-std-fs)         │     targets   ← per-target inputs
                                            ├─► binding modules       [generated, internal]
                                            ├─► cargo workspace + main()  [generated]
                                            ├─► targets/macos-sysroot [generated, framework union]
                                            └─► roc glue ──► roc_platform_abi.rs
                                                              │
                                              cargo ──────────┴──► libhost.a
                                                                     │
                                            roc build app.roc ───────┴──► binary
```

Everything above the `roc glue` line is hematite. Everything below is the
existing, unmodified Roc toolchain.

## Gates

### H0 — Link-shape spike suite ⚠ highest NO-GO risk, runs first  ✅ COMPLETE 2026-09-04

Nothing in this plan survives H0 failing, and no other gate may shape itself
around an assumed result. Every platform in the tree today is exactly one
archive (`inputs: ["libhost.a", app]`); nothing has ever linked two.
`crates/host-im/src/dbx.rs` is explicit that this class of question "can kill
the project outright and cannot be worked around."

- **(a) Two-archive link.** Two independently built Rust staticlibs, each
  defining hosted symbols under readable mangled names
  (`hematite__a__ping`, `hematite__b__pong`), one hand-written `main.roc`
  binding both, `inputs: ["liba.a", "libb.a", app]`. A Roc app calls one symbol
  from each and both return.
- **(b) Framework sysroot union.** Two components declaring disjoint framework
  sets; generate the union `targets/macos-sysroot` by the existing recipe's
  rule; confirm the linker's TBD-driven `-framework` auto-add picks up both and
  neither component's frameworks leak into a build that doesn't declare them.
- **(c) Duplicate bundled natives.** Two components that each vendor a C
  dependency (`rusqlite/bundled` is the known-hard case — `dbx.rs` proves the
  single-archive path works). Determine whether duplicate `sqlite3.o` members
  across two archives are a link error, a silent first-wins, or fine. This is
  the one sub-spike whose failure is *expected* and needs a written policy
  rather than a fix — hematite cannot repair the roc linker's missing `-l`
  mechanism, only report legibly.
- **(d) Panic across component frames.** G1's D11d already established that
  unwind crosses Roc frames, is catchable at the host boundary, and runs **no
  Roc-frame cleanup** — so "catch-dump-abort, never rely on unwind for cleanup"
  is settled. What is *not* settled is N components: does each component's Rust
  `Drop` run as the unwind passes its frames, and is a partial teardown worse
  than none? Outcome is a written rule in the design log, either "generated
  `main()` catches at the boundary and aborts without running component
  teardown" or "teardown is safe and ordered."
- **(e) Multi-hosted-module composition.** Does a *single* Roc platform accept a
  `hosted {}` block that is the mangled union of symbols contributed by two
  separate host-bearing modules? Every platform in the tree has exactly one
  `hosted` block (roc-solid, seahaven, tower) or zero (`platform-im`); nothing
  has ever aggregated two. This is the "mangled union" the architecture diagram
  promises and it is an H0-class unknown, not an H2 detail — pulled forward here
  so H2 is not the first place it is discovered. A hand-written `main.roc` whose
  `hosted {}` names `hematite__a__ping` and `hematite__b__pong` from two modules
  must `roc build` and both symbols must resolve.
- **NO-GO handling:** (a) failing is fatal to D4 (source composition) and forces
  a redesign around a single generated crate that `include!`s component sources
  — dated note and a decision before H2. (c) failing is a documented limit on
  component weight, not a redesign. (e) failing means the "mangled union" hosted
  shape is unavailable and D6/D13 need a single-hosted-module rework — a
  redesign, dated note before H2.
- **Exit:** (a), (b), (d), (e) pass; (c) has a written policy. `just h0` green.

> **Outcome** ([note](../notes/2026-09-04-h0-link-shape.md)): all five PASS, no
> NO-GO. Multi-archive linking is real (`spikes/h0/`, 40+2=42). Hosted union
> resolves across archives (H0e). Panic needs `extern "C-unwind"` or it aborts
> with zero teardown (H0d). Duplicate vendored natives link *silently* first-wins
> — hematite must `nm`-scan and reject (H0c). Framework sysroot union is a
> symlink directory the linker auto-discovers (H0b). Two things the linker won't
> enforce and hematite must: one runtime provider, no duplicate non-hosted
> symbols.

### H1 — Notation spike (paper only, parallel with H0)  ✅ COMPLETE 2026-09-04

Cheap, and it gates the manifest format rather than any code.

- Express roc-solid's two hardest crossings in the superset notation:
  `dep_thunk! : U64 => Box(({} => a))` and
  `register_binding! : List(U64), Box(({} => Str)) => U64`.
- **Encode the D3a addendum as a notation rule, not a comment.** G1 found that
  funnel-crossing closures with inferred open-row or unbound dep types
  typecheck, build, and then *silently corrupt memory when fired*. The IDL must
  make an under-annotated closure inexpressible — closed concrete dep types are
  a well-formedness condition on the `closure` extension, checked by hematite.
- Mark the WIT-projectable subset boundary on seahaven's ~60 symbols. Confirm
  the `U128` gap (`utc_now!`, the three `file_time_*`) is the only one, and
  decide its lowering (`tuple<u64,u64>` vs superset-only).
- **Exit:** a written notation sketch covering both crossings *and* encoding the
  D3a well-formedness rule, or a dated note naming the specific construct the
  superset cannot yet express. (A sketch that simply says "can't be done" does
  **not** pass — the note must name the missing construct.)

> **Outcome** ([note](../notes/2026-09-04-h1-idl-notation.md)): no NO-GO. The
> superset expresses both hard crossings (`dep-thunk`, `register-binding`) via
> `box<T>` + `closure<…>{donated|borrowed}`, and the whole seahaven boundary.
> Projectable subset = core WIT types + a `u128 → tuple<u64,u64>` projection
> rule (keeps the four `U128` clock/file-time symbols in-subset). D3a is now a
> checkable well-formedness rule: a `closure`'s arg/return types must be closed
> and concrete or hematite rejects the interface before `roc build`.

### H1b — Cross-component `requires` splice spike ⚠ the H7 killer, spiked early  ✅ COMPLETE 2026-09-04

Pulled out of H7 because it is the single most segfault-prone surface in the
tree and the plan's own prime directive (spike before build) was not being
applied to it. `platform-im`'s `requires` (145 lines) references `Element`,
`Env`, `Cmd`, `Scene`, `CapVal`, `Id` — nominals owned by *other* components —
and the file's own comments document that this compiler **segfaults with no
diagnostic** on (i) a type *alias* imported across type modules, and (ii) an
import missing from `exposes`. D18-as-C (below) has hematite splice the
`requires` verbatim while resolving the driver's declared `[requires.uses]`
types to their post-rename canonical modules.

- Hand-write a two-component fixture: a driver whose `requires` names a nominal
  (`Widget`, say) owned by a *second* component, declared in the driver's
  `[requires.uses]`. Compose so the second component is renamed (D14). Confirm
  the spliced `requires` links and runs — not segfaults.
- Force the alias path: wire the referenced type through a D13 binding module
  and confirm whether it reaches the `requires` as the original nominal (safe)
  or a re-exported alias (the documented segfault). If the latter, D13's binding
  modules must **re-export the original nominal, not alias it**, for any type a
  driver `requires` names — record that as a hard rule.
- Force the missing-export path: a `[requires.uses]` entry hematite fails to add
  to `exposes` must be caught by hematite as a compose error *before* `roc
  build`, since the compiler turns it into a silent segfault.
- **Exit:** the renamed-nominal splice links and runs; hematite rejects a
  missing-export before invoking `roc build`; a dated rule on nominal-vs-alias
  re-export exists. NO-GO ⇒ D18/D5 need a non-splice mechanism (hematite parses
  and rewrites the `requires` — the D13 cost C was chosen to avoid), decided
  before H3.

### H2 — Hand-composed reference platform  ✅ COMPLETE 2026-09-04

The golden fixture. Written entirely by hand, no tool.

- Two host components (stdio + fs primitives, split so they are genuinely
  separate), one pure-Roc derived component (a small `Path`-shaped library over
  fs), one driver (CLI, `main! : List(OsStr) => Try({}, [Exit(I32), ..])`).
- Hand-write everything hematite will later generate: `platform/main.roc`, the
  internal binding modules, the cargo workspace, generated `main()` with
  lifecycle ordering, the sysroot.
- A real app builds against it with stock `roc build` and does I/O.
- Include one **interposer** in the wiring (`fs = audit-log(cap-std-fs)`) so the
  DAG case is in the fixture from the start rather than retrofitted.
- **Exit:** app runs; the whole composition is checked in under
  `tests/golden/two-component/` as the fixture H3 must reproduce.

> **Outcome** ([note](../notes/2026-09-04-h2-reference-platform.md)): a
> `reader-cli` world (5 host archives + a pure-Roc `Path` + interposer
> `fs = audit(capstdfs)`) links and runs — `reader platform/main.roc` prints
> `32 lines` (matches `wc -l`). `build.sh` reproduces it and is the runnable
> spec for H3. Two findings fed forward: (1) cross-component host calls resolve
> at the final roc link via extern, **never** a cargo dep (a dep bundles and
> duplicates — the H0c footgun); (2) the pinned glue can't build a
> `RocList<RocStr>` from the host, so the driver takes `{}` and the path comes
> through an `env` interface as one `RocStr` — the `List(OsStr)` driver returns
> once the upstream glue redesign lands list constructors.

### H3 — The composer, reproducing H2  ✅ COMPLETE 2026-09-04

Now write the tool, in Rust, with H2 as its only acceptance test.

- Manifest parsing (`.wit`-shaped interfaces + world TOML), DAG resolution,
  cycle detection, deterministic topological order, version unification.
- Codegen: `main.roc`, binding modules, cargo workspace, `main()`, sysroot.
- Driver `requires` spliced through as literal text — hematite does not parse it.
- Provenance headers and per-declaration origin comments on every generated file.
- **`roc check` the composed platform before `roc build`** (H1b): converts the
  compiler's silent SIGSEGV on an `exposes`/`requires` mismatch into a
  diagnostic. Also statically assert `exposes ⊇ requires.uses`.
- **Exit:** `just h3` produces output byte-for-byte identical to
  `tests/golden/two-component/`. Diff is the test.

> **Outcome** ([note](../notes/2026-09-04-h3-composer.md)): `hematite compose`
> (Rust, `src/`) regenerates the fixture byte-for-byte and the result builds and
> runs (`32 lines`). `tests/golden/two-component/verify.sh` is the gate. Two
> compose-time checks reject before roc runs: `requires_uses ⊆ exposes` (H1b
> segfault) and exactly-one-runtime-provider (H0c). Open: the duplicate-symbol
> nm-scan and folding glue+cargo+roc build into the tool (currently build.sh).

### H4 — Roc shims, `cell`, and Tier 1  ✅ COMPLETE 2026-09-04

- The typed handle-based `cell` component in the baseline
  (`Cell.new!`/`get!`/`set!`) — not roc-solid's `U64`-slot store with its
  unchecked downcast.
- An in-memory filesystem shim, written in Roc, satisfying the same fs interface
  as the host implementation. The derived `Path` component's source must not
  change by one byte between the two wirings — that is the actual assertion.
- **Tier 1 proof:** extend a *published* platform with a pure-Roc component,
  reusing the prebuilt `libhost.a`, with no cargo and no `roc glue` run.
  Confirm hematite reports the tier and warns on ABI fingerprint mismatch.
- **Exit:** both wirings pass the same app-level test; Tier 1 extension builds
  with the Rust toolchain removed from `PATH`.

> **Outcome** ([note](../notes/2026-09-04-h4-shims-cell-tier1.md)): the Roc
> shim `memfs` fulfills `filesystem` with `Path.roc` byte-identical across the
> host-fs and Roc-fs wirings (`tests/golden/roc-shim/`); a cell put!/get!
> round-trip asserted inside every read proves host-backed state from a Roc
> shim (D12). Tier 1: a pure-Roc `Greet` module extends the prebuilt H2
> platform with only `roc build` — cargo and glue unused, archives reused.
> Codegen now handles Roc-implemented wiring points (no hosted entry; binding
> module from the shim). Finding: a Tier-1 add needs both an exposes and an
> import edit, or roc build segfaults (H1b class).

### H5 — Seahaven migration + the substitution proof  ◑ PARTIAL 2026-09-04 (substitution slice proven; full migration remaining)

The gate that makes "alternate implementation" mean something.

- Decompose seahaven into interfaces (stdio, fs, process, env, clock, random,
  tty, regex, signal) plus derived pure-Roc components. `IOErr` and `OsStr` land
  in a `roc:cli` userland package, not in hematite.
- Compose it back into a platform. `rocjust` — the original client — must build
  and pass its suite against the composed platform.
- Implement the same primitive interfaces against libc (basic-cli-shaped) and
  compose a second platform. **The derived layer is shared, unmodified, between
  both.** ~1,500 of seahaven's 2,325 Roc lines exist once, not twice.
- Emit the `.wit` projection for the projectable subset; report the `U128` gap.
- **Exit:** `rocjust` passes on both compositions; the shared derived components
  are byte-identical in each.

> **Outcome — PARTIAL** ([note](../notes/2026-09-04-h5-seahaven-slice.md)): the
> substitution + shared-real-derived-layer theses are proven at seahaven-source
> scale on the **stdio** surface (`tests/golden/seahaven-slice/`): seahaven's
> actual `Stdout.roc`/`Stderr.roc` (byte-identical to upstream) run over a
> hematite stdio interface, and two interchangeable host impls (`std-stdio`,
> `capture-stdio`) produce different output from the same derived layer. Drove
> two tool changes: `resolve::sanitize` (component-name → valid C identifier for
> mangled symbols + archive names) and `--world`. **Remaining (documented, ~weeks):**
> the other ~7 interfaces incl. the 765-line `Path.roc` (20 fs primitives, U128
> times), the brush cap-std vs libc two-impl at full surface, and `rocjust`
> green. The research theses are settled; the rest is mechanical execution.

### H6 — Per-app worlds

The product promise: baseline by URL, straightforward extension.

- Publish the composed CLI baseline as a versioned tarball (sources + prebuilt
  `targets/` + ABI fingerprint). An app consumes it by URL with no `hematite.toml`
  and no toolchain.
- One app adds a pure-Roc component (Tier 1). One app adds a host component with
  a vendored native dep (Tier 2) and rebuilds.
- Hematite reports the tier transition when a Tier 1 world gains a host
  component — the cliff must be visible, not discovered.
- **Exit:** both apps build; the Tier 1 app builds without cargo.

### H7 — roc-solid `platform-im` ⚑ closing scaling gate

The real test, and the gate most likely to force a redesign. Sequenced last on
purpose: everything before it is known-good mechanism.

- `platform-im` is the imports-zero, exports-only driver — a good first roc-solid
  shape precisely because it has no `hosted` block to decompose.
- Split `crates/host-im` along its seams: the engine and frame loop stay in the
  driver; `dbx.rs`, `docsvc.rs`, `audio.rs`, `assets.rs` and `eink/` become
  components with their own worlds. **The success criterion is that colorhunt's
  binary contains no sqlite.**
- Replace `Request.HostOp(Str, Str)` — the stringly-typed unchecked escape hatch
  invented because there was no composition — with typed components. This is the
  north star; a migration that leaves `HostOp` in place has not tested anything.
- Exercise `roc:test/quiesce` for the first time: a headless test that waits on
  more than one effect source.
- The cross-component `requires` splice this driver forces (145 lines naming
  `Element`, `Env`, `Cmd`, `Scene`, `CapVal`, `Id`) is **de-risked at H1b**, not
  discovered here; H7 is the first real driver to exercise `[requires.uses]`
  (D18-C) at full scale, not the first to find out whether it works.
- **NO-GO handling:** if the superset cannot carry `platform`'s (not `-im`'s)
  closure boundary after H1 said it could, that is a dated note and a v2 problem,
  not a v1 failure.
- **Exit:** at least two of the four apps run on composed platforms with
  divergent worlds; **`nm` on colorhunt's binary shows zero sqlite symbols**
  (the union-host disease, cured and mechanically checkable — not a subjective
  size delta).

## Risks

- **R1 — Multi-archive linking (H0a).** Highest, and mitigated only by running
  it first. No fallback is cheap.
- **R2 — Duplicate vendored natives (H0c). ✅ RESOLVED-WITH-POLICY 2026-09-04.**
  Measured: duplicate non-hosted symbols across archives link *silently*,
  first-in-`inputs` wins (output 80 vs 4 by archive order) — no diagnostic, and
  memory-unsafe if the two copies differ. The linker will not catch it, so
  hematite must: at compose time, `nm`-scan every component archive and reject
  any non-hosted, non-runtime symbol defined by more than one component (same
  check enforces "exactly one runtime provider"). See
  `notes/2026-09-04-h0-link-shape.md`.
- **R3 — Binding-module indirection cost (D13).** Measured at `--opt=speed` the
  way `im-layout` makes its claim falsifiable — it fails at dev and passes at
  speed. Folded into H3 rather than given its own gate; if the hop doesn't
  flatten, the fallback is generating direct calls at the cost of D12's
  implementation-transparency.
- **R4 — Unchecked host implementations (D15).** Accepted. Nothing verifies a
  hand-written `#[no_mangle] extern "C"` against its Roc declaration; seahaven
  alone has ~60. The upstream ABI fingerprint covers version drift, not
  per-symbol signatures. Revisit if H5 surfaces a real mismatch bug.
- **R5 — Compiler churn.** This repo tracks roc `main` like the others. Every
  `roc` invocation gets the `perl -e 'alarm shift; exec @ARGV'` cap and a
  pinned `~/.bin/roc`, per roc-solid's Justfile — the cap is a gate, not a
  convenience.
- **R6 — Single-version-per-world (D16).** Couples the ecosystem to the
  baseline's release cadence. Fine at one author; compatible version *ranges*
  are the eventual softener.
- **R7 — Cross-component `requires` splice (D18-C).** *Was missing from this
  list — added after adversarial review.* A driver's `requires` names other
  components' nominals; renames (D14), alias indirection (D13) and missing
  exports all fail as **silent segfaults** on this compiler, per `platform-im`'s
  own comments. Mitigated by `[requires.uses]` (D18-C) and spiked early at H1b.
  Still the likeliest H7 killer if the nominal-re-export rule turns out
  insufficient. No cheap fallback: the alternative is hematite parsing Roc.
- **R8 — Derived layer imports monolithic `Host`, not `fs` (D2/D13 tension).**
  Sharing seahaven's ~1,500 derived lines across implementations needs
  `import Host` → `import fs` rewrites, which D13 forbids for *component* source.
  Resolved by ruling migration ≠ composition: decomposing a legacy platform into
  components is a one-time authored rewrite; D13's "never rewritten" governs
  composition of already-decomposed components. H5 must not claim the libc host
  is a drop-in until it also replicates seahaven's sandbox-flavored primitive
  semantics (virtual `canonicalize`, always-false `isatty`, session-scoped pid).

## Non-goals (v1)

- Shared-nothing WASM component composition (D22c). Revisited later.
- Binary component distribution (D4).
- Roc shims serving host consumers (D19) — async interfaces are host-shim
  territory by thread affinity, not by policy.
- Blessed core vocabulary (D7). `roc:cli` is userland; promote only what two
  independent worlds both need.
- Generated host-side trait stubs (D15). Upstream's glue redesign owns that
  ground.
- Diagnostic rewriting (D23). Provenance comments and readable mangling only;
  parsing roc's diagnostic format is a tool that will lie about locations.
- Any generated artifact in git (D23).
